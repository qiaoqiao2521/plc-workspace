# TIA Portal：I/O 与属性（Properties）检查清单

## A. 组态后必须确认的 I/O（先做这个再写逻辑）

把下表补齐（没有就先做“接口版”，不要把地址写进逻辑块）。

### 1) 数字量 DI（Digital Input）

- 信号名（建议 `DI_` 前缀）
- 地址（如 `%I0.0` / `%I1.2` / 设备通道）
- 常开/常闭含义（1=触发还是 0=触发）
- 是否需要滤波/去抖（ms）
- 异常/断线时的期望处理（报警、停机、保持上次）

### 2) 数字量 DO（Digital Output）

- 信号名（建议 `DO_` 前缀）
- 地址（如 `%Q0.0`）
- 允许动作的前置条件（互锁/联锁/急停）
- 上电默认状态（0/1）、复位逻辑

### 3) 模拟量 AI（Analog Input）

- 信号名（建议 `AI_` 前缀）
- 地址/通道（如 `%IW64` 或设备通道）
- 原始量程（常见：0..27648 或 -27648..27648）
- 工程单位量程（如 0..10.0 bar、4..20 mA 等换算后单位）
- 滤波（滑动平均/一阶滤波）与采样周期
- 断线/越界检测策略与报警动作

### 4) 模拟量 AO（Analog Output）

- 信号名（建议 `AO_` 前缀）
- 目标工程单位范围与原始输出范围
- 失效/急停时输出安全值（0、保持、回零等）

## B. TIA 项目与块属性（Properties）必须明确的项

> 这些项会直接影响可监视性、HMI 访问、DB 结构与兼容性。生成代码前必须问清楚或明确假设。

### 1) Optimized block access（优化块访问）

- 是否启用（项目/DB/块层级都可能有设置）
- 影响点：外部按绝对地址访问、某些旧系统/工具兼容、DB 内部布局变化

### 2) DB 策略：实例 DB vs 全局 DB

- FB 调用是否允许自动生成**实例 DB**（最常用、最省事）
- 是否需要手工建全局 DB（例如与 HMI/上位机规范、版本兼容、结构固定有关）

### 3) Retain / 初始值

- 断电后需要保持的状态（例如累计量、配方、手自动选择、故障锁存）
- 断电后不应保持的状态（例如瞬时步骤、临时滤波）

### 4) 调试/监视体验相关

- OB1/Main 是否要求用 LAD 组织（建议：每个功能一张网络，便于监视）
- 是否需要提供强制/仿真点位（建议放在 I/O mapping 层或测试 FC）
