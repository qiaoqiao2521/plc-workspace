# PLC Logic Harness v1 — SpecMesh 改造计划

日期：2026-11-06。基线：`master@4089870acb6a70acaf5bd0ca196d9d7ed88b1690`。
状态：**计划已编写，实施未开始**。本次只改变项目记忆，不改变 PLC、生成器、检查器或运行环境。

## 目标与背景

只聚焦“需求 → 逻辑准确的 LAD / SCL → 有明确范围的验证结果”。在现有 SCL 检查与有限修复闭环上增量改造，不建设 PLC 全家桶。

用户要求工业场景严谨、Harness 严格约束。这里将其落实为：Harness 约束需求、生成范围、工具调用和交付判定，不能替用户决定工艺，也不接管通用 Agent 编排。SpecMesh 只记录目标、事实、决定、计划与进度；本次不是改造 SpecMesh 自身。

调查报告提供“逻辑设计、确定性构建、独立验证”的方向，不直接成为供应商能力或正确率的证据。基线事实和阅读范围见 [findings.md](findings.md)，接续状态见 [progress.md](progress.md)。

## 非目标与冻结边界

- 不新增 Agent 角色、调度器、长期记忆服务、MCP 工具大全或跨项目 Harness 平台。保留当前 mcode/CM 路径；不把替换它作为本计划前提。
- 不接入现场 PLC，不自动下载、RUN/STOP、强制变量或写真实 I/O；不生成或修改 F 安全逻辑。普通停止/外部抑制反馈不能标成安全功能认证。
- 不做 HMI、SCADA、FBD、GRAPH、完整 PLC IDE、完整仿真器或多厂商兼容矩阵。
- 不把 TIA、PLCSIM、Windows、任何第三方 MCP 项目设为核心必装依赖。可借鉴博途的工程结构与诊断方式，但适配后置。
- 不重写 `FB_MainSequence` v0.3、其扫描契约、规范 ST、派生文件或已有证明。不能把该示例的持续 Enable/故障规则套给其他工艺。
- 不因编译通过、两种输出一致、模型审阅通过或某个基准全过，宣称工业安全、全面语义等价或任意 PLC 程序正确。

## 必须落实的约束

| ID | 约束 | 验收时怎样判定 |
|---|---|---|
| R1 | 工艺来源明确 | 每项关键行为关联需求或经确认的合同；停止、复位、重启、反馈含义有冲突时阻断动作逻辑生成，不只是附带 questions。未知物理地址允许留在接口草稿中，但不得编造。 |
| R2 | 能力边界显式 | 目标语法/指令子集、调用模型、状态与计时单位在任务开始前确定；不支持的构造明确拒绝该目标，不能静默丢弃、改语义或降级后仍称通过。 |
| R3 | 同源双输出 | 新增受限路径由一份有类型、可检查的 Logic IR 确定性生成 SCL 与 LAD；LAD 承载真实控制逻辑，不用“调用一个 SCL FB”的外壳冒充 LAD 生成完成。 |
| R4 | 预期独立 | 验收预期来自确认的合同和独立测试，不从被测实现的输出反推；生成/修复步骤不能改需求、测试预期、门禁配置和证据结论。 |
| R5 | 分项证据 | 结构检查、编译、行为、LAD/SCL 对照、目标平台检查分别记录状态、对象、范围和原因。编译通过不代表行为检查通过。 |
| R6 | 未知不放行 | 必选检查的 fail、unknown、not_run 均不能授予对应验收等级。可选检查是否适用由明确目标决定，不由模型临时豁免。 |
| R7 | 修复不能作弊 | 保留现有默认最多两轮修复；每次修改后重跑受影响检查。IR 路径修复 IR 并重生两种输出；旧 SCL 路径继续源码修复，但不得假称已得到等价 LAD。 |
| R8 | 证据不过期复用 | 需求、合同、IR、生成器或产物变化后，旧结论标为失效并重验受影响范围；导入记录仅是历史记录。复用既有来源关联，不新增逐阶段强制哈希或逐字节读回仪式。 |
| R9 | 判定不由模型签发 | 模型可解释问题、建议修复，不能写入权威 pass 或覆盖工具失败。缺工具、崩溃、超时、被取消分别保留原因。 |
| R10 | 严格但不阻塞独立工作 | 外部 TIA 不可用只阻塞 Siemens 验收，不阻塞可独立完成的离线子集开发；未决工艺只保留规格草稿，不以无限重试代替决策。 |

这些是本项目拟实施的产品规则，不冒称 IEC 强制条款。行为策略必须属于具体合同；例如“停止优先”不是在这里替所有现场设备统一规定的通用语言规则。

## 最小目标结构

```text
已确认需求 + 类型化接口 + 扫描合同
                ↓
         AI 提议受限 Logic IR
                ↓
       确定性的结构/能力检查
                ↓
      SCL 生成      LAD 图生成与预览
           ↘          ↙
       独立预期 + 产物级检查 + 有界修复
                ↓
     候选文件 + 分项结果 + 反例/限制
                ↓ 可选、后置
       TIA 导入/编译与平台验证
```

Logic IR v0.1 是**拟新增的最小合同，不是通用 PLC 语言**。优先复用现有请求和结果结构，在其旁增加版本化的受限数据结构，不重建整个工作台。

最少表达：有类型的符号、初值、持久/临时状态、表达式节点、执行/网络顺序、条件与状态转移、输出所有权、调用模型、合同引用和未决项。表达式用可检查的节点与符号引用，不以任意 SCL 字符串藏入 IR。新生成任务的 IR 不取代历史 `02_src/st` 的权威地位。

首个子集只含 BOOL、常开/常闭、串并联、普通线圈及为样例所需的内部记忆；随后按明确合同增加 UINT 扫描计数与有限状态。真实 TON 的时间语义、掉电保持、任意循环、指针、厂商特殊指令暂不默认支持。扫描次数不能标成毫秒，重建实例不能冒充真实掉电恢复验收。

LAD 初期输出为明确标识的内部图结构和可审阅图形，不冒称 TIA 可导入文件。图中的连线、网络顺序、符号与生成的可见触点必须一致；只验证 IR、只比较图片或只检查 JSON 格式都不够。

## 交付状态与放行规则

沿用现有 `pass / fail / unknown / not_run`，另记录每项检查的适用目标与必选性，不增加一个掩盖细节的“工业级通过”按钮。

| 目标 | 必要证据 | 明确不能据此声称 |
|---|---|---|
| 候选/审阅草稿 | 结构可读、来源与未决项清楚 | 逻辑已验证、可上机 |
| 受限子集 SCL 验证 | 合同完整、子集检查、真实编译、该候选的独立行为测试 | TIA 已编译、硬件已验证 |
| 受限子集 LAD/SCL 对照验证 | 上述证据 + LAD 拓扑/符号检查 + 从实际输出图执行的行为结果 + 双输出对照 | 任意输入/无限时间的等价证明、Siemens LAD 验收 |
| Siemens 目标验证 | 明确 TIA/CPU/版本、实际导入与编译；所声称的仿真能力还须独立运行记录 | 现场工艺、机械与功能安全验收 |

无行为合同的任务最多显示“编译通过，行为未验收”；不得借 `report.status=pass` 提升为逻辑通过。`reviewed_draft` 的兼容处理须明确它只代表哪些已完成检查。

失败候选、差异与诊断仍可查看和导出用于排错，但不能附带有效放行状态；未决工艺产生的规格草稿与可执行候选须区分。可选 TIA 检查未运行，不影响离线子集结果，也不能被隐藏或自动记为通过。

## 实施切片与停止条件

### S0 — 本次：计划与项目入口

产物：本目录三个文件，更新 `PROJECT.md` 的目标/优先级与 `AGENTS.md` 的阅读入口。保留 `docs/ARCHITECTURE.md` 对现有实现的描述，不提前写成未来架构已经存在。

验收：文档能区分已实现、拟实施、历史记录和未验收；提交不含任何执行代码、依赖或现场配置。完成后不自动展开实现。

### S1 — 先让现有 SCL 结果说真话

从 `candidate-validation.py`、`mcode-workflow.py` 和前端结果展示切入。按任务目标明确必选检查，拆开编译通过与行为未运行；旧工程导入保留记录但不恢复本次验收权限。用现有 `conveyor-12-v1` 作为第一条真实行为路径，不先建设通用测试平台。

验收：覆盖编译通过/行为 not_run、行为 fail、工具 unknown、取消、旧记录导入、来源变化和模型伪造 pass；所有不满足目标的组合均被拦截，合法候选仍可审阅。既有固定编译/扫描回归继续通过。明确分开夹具测试与真实 mcode/CM 运行；缺少在线环境时记为未验收，不能拿夹具替代。

停止条件：状态分项和升级规则未通过负向测试，不进入新增生成能力；在线模型不可用时可继续独立的确定性开发，但不关闭在线验收项。

### S2 — 第一个双输出闭环：启停自锁

建立一个经审阅的**合成基准合同**：明确正常启动、停止与启动同拍、Start 持续按下、释放后重启、初值与使能行为。这些只属于该基准，不成为真实设备默认工艺。实现最小 IR、SCL 生成、串并联 LAD 图与预览，接入 S1 的分项结果。

验收必须同时满足：

1. 同一确认输入重复生成，输出逻辑与结构稳定；未声明符号、类型冲突、非法节点/连接和多写冲突被拒绝。
2. SCL 由真实 matiec 编译并运行；LAD 由独立的小型有界图执行入口读取**序列化后的生成图**，不能绕过产物直接运行原 IR。两者对照独立预期和逐扫描轨迹。
3. 能拦截：把并联写成串联、反转一个触点、漏停止条件、保持 Start 后错误重启、重复写输出、改变更新顺序。每个错误版本必须有能指出违例的检查，不能仅凭工具故障 unknown 声称捕获了语义错误。
4. 页面显示 LAD 与 SCL，支持导出/重开和状态失效。LAD 不只是一个 SCL FB 调用块。预览符号、触点极性和连接与图数据对应。
5. 做一次真实模型→规格→IR→双输出→检查的在线演示；再用故意错误的候选检查诊断/修复。记录真实结果、修复次数和未完成项，不用模型夹具充当在线验收。

停止条件：只完成 Schema、漂亮图形或两份互相一致的错误程序，均不算闭环。S2 未验收前不增加指令种类、编辑器或厂商。

### S3 — 第二个闭环：保留合同的输送带顺控

复用现有 `conveyor-12-v1` 的接口和已固定规则，补足新增 LAD 表达需要的有限状态与 UINT 扫描计数；不得替换成 `FB_MainSequence` 的另一套 Enable/Reset 策略。当前合同未覆盖的控制组合先记录并审阅预期，不让生成器自行选择。

验收：启动不算等待，第 1～11 次等待不超时，第 12 次才超时；到位与截止同拍按合同处理；停止撤销动作，保持 Start 不重启，Done 单拍。增加同时输入、计数边界、非法状态及具体恢复规则的已确认用例。LAD 与 SCL 分别通过预期，并通过轨迹对照；改变阈值/优先级/边沿消费的错误变体必须失败。

旧 SCL 修改仍可走现有源码闭环；无法解析到受支持 IR 时明确保持 SCL-only，不能声称任意 SCL 已被转换成 LAD。此切片不承诺真实 TON、掉电保持或任意状态机转换。

停止条件：S2/S3 只保留两个可复现演示作为首版；没有具体失败案例或需求，不扩功能清单。

### S4 — 后置可选：最薄 TIA 适配

仅在确有导入/编译需求及合法可用环境后启动。先核对目标版本、官方格式和小型参考模板，验证一个最小块的导入、编译、诊断回传；再决定 SimaticML 或 SIMATIC SD 的实现，不预先承诺跨版本兼容。

接口只负责传递明确产物与返回结构化诊断。博途组件留在可选主机侧；Linux 核心不因未安装它而失败。不引入第三方完整 MCP 服务作为主依赖，不复制未经核实或许可不明的实现。

验收：至少一个指定版本的真实导入/编译成功样例和一个失败样例；可选环境缺失明确标记 not_run/unknown。需要 PLCSIM 时另验，不从编译结果推导仿真通过。任何现场下载/写入不属于本计划。

## 验收记录与评价

每次只记录必要信息：任务/候选身份、确认合同版本、能力范围、实际输入与预期、运行工具/版本、分项状态、首个反例、修复次数、产物位置与剩余限制。复用现有任务目录和报告；不另建证据管理平台。

按具体任务与子集分别报告首次编译、行为通过、双输出对照、歧义拦截、错误变体检出和人工修正情况，保留样本数与分母。两个演示不能外推通用准确率；同源生成和有限轨迹一致都不是全空间证明。形式验证只在属性、模型、边界与后端可核实的范围使用，不作为每个微小变更的强制大工程。

## 风险、回滚与收口

- **公共错误源**：两出口共享 IR 可能一起错。用独立预期、实际产物执行和错误变体降低风险，不能靠互相比对自证。
- **验证面窄**：现有命名合同不覆盖任意新需求。未覆盖维度显式保留，不以编译或文本审阅补成通过。
- **方言差异**：Linux 子集结果不证明 Siemens 兼容；适配前不把 vendor 特性删掉后声称语义保持。
- **合同误迁移**：保留抽象核心与输送带样例不同的生命周期，需求未确认不统一重写。
- **运行边界**：现有临时子进程不是敌对代码安全沙箱；不向公网开放任意代码执行，不增加设备凭据或主机写权限。
- **状态升级破坏兼容**：旧工程仍可读/导出，旧 pass 不自动获得新等级；保留既有历史证据，不改写历史为通过或失败。

按切片单独提交。失败时撤回对应切片的生成入口或代码提交，保留诊断，不放宽门禁求通过；来源变化的旧结果仍保持失效。新 IR 路径可停用，旧 SCL 草稿路径保留其真实范围。计划 PR 不自动合并，不自动扩到下一切片。

前沿跟踪沿用现有“PLC 前沿与路线雷达”，只把核实后的变化记为做/观察/不做及触发条件；不另建抓取平台，不因新论文或工具数量增加就改路线。

## 成功标准与下一步

首版成功不是“框架齐全”，而是：**一个明确需求能得到含实际逻辑的 LAD 和 SCL；正确候选通过其独立检查，已知错误被拒绝，未知能力如实标记，现场权限始终不被越过。**

下一步只实施 S1 的证据分层和错误判定回归。完成后再推进 S2；不从新增目录、安装博途或增加 Agent 开始。
